2026-08-30：根据设置页「使用技巧」制作 Compose 局部界面演示。按右滑侧栏、双指缩放、迷你栏定位、封面长按菜单、文件夹层级、自定义排序锁定拆为六页；Offload 排查保留原文字，不自动修改音频设置。

## 交互与边界

- 新安装进入软件不再直接打开教程。选择全盘或文件夹扫描并实际进入扫描状态后，仅首次弹出「扫描中，是否打开使用技巧？」；标题居中 18sp，左侧「是」、右侧红色「否」均为 16sp。拒绝读权限、取消选目录或未真正启动扫描均不触发。
- 选择「是」才打开教程；选择「否」或系统返回记录完成，后续扫描/启动不再自动询问。弹窗不因点空白区域关闭。教程中的跳过、完成或第一页系统返回仍记录完成，其他页系统返回退一页；Activity 状态恢复保留询问窗口和已接受教程的页码。进程全新启动不强制恢复已询问过的教程，可从设置手动重看。
- Application 初始化其他设置前检查已有 `mica_settings.xml`，存在则视为旧安装，不自动展示。没有任何设置文件的旧空安装无法与新安装区分，可能展示一次。清空曲库不重置教程。
- 设置 → 使用技巧 → 重新查看教程。手动重看从第一页开始，不改完成记录和首次进度。
- 外部音频打开会隐藏首次询问/教程，不阻挡指定文件播放。通知权限申请恢复原启动时机，不再等教程关闭。询问和教程均不暂停扫描、不改音频或播放队列。
- 使用独立 Dialog 窗口，覆盖双 ComposeView 播放浮层；返回/触摸由教程窗口处理。
- 现有技巧「左滑打开侧栏」与 `homeDrawerSwipe` 不符，已改为向右滑打开；未修改真实手势。定位要求当前曲目存在于曲库；文件夹切页仅限「层级浏览」模式，且要求有相应层级。

## 状态与容量审计

- owner：`UsageTutorialPreferences`，独立 SharedPreferences 文件，初始化/首次邀请 claim/进度/完成写入共用 `@Synchronized` 入口。`scan_invitation_shown` 是单调的一次性 claim，完成状态优先；两个窗口/重复扫描不能重复领取。
- `UsageTutorialScanInvitation` 使用 `snapshotFlow` 直接观察 `library.isScanning`，不等下一次界面重组才读取。collector 恢复后、claim 副作用之前重新读取扫描状态和外部打开开关；无 IO 等待和后台持久化回调。SharedPreferences.apply 负责磁盘排队。完成后拒绝旧的 claim/页码写入；重扫后和完成后重新挂载的 UI 测试覆盖这一点。动画只写页面局部 Animatable。
- 不改扫描编排、generation 或 Room 写入：扫描仍由原有 `scanGeneration`、`storeRevision`、`storeSyncMutex` 协议管理，教程只消费既有布尔状态，不接受扫描结果，不发布媒体快照。
- 不读取曲库和歌词，不增加扫描或媒体快照工作。10,000 首完整逐字歌词/8 GB 基线下，教程新增内存与歌曲数量无关：仅十二个空歌词的示例 Song、当前页最多十二个歌曲行、动画值及现有缺省封面资源，没有全量歌词解析、复制、媒体加载或新增封面缓存。
- 验证目标：首次入口、翻页/返回、跳过/完成、进度恢复、旧安装迁移、设置重看、浅深色、横屏、减少动效；结果以实际构建和设备验证记录为准，不把静态预览视为真机验收。
