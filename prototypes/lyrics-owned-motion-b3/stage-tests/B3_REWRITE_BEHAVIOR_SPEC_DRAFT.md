# B3 重写前行为契约草案（v0，待确认）

> 状态：**DRAFT / NOT APPROVED**。2026-10-12。
> 依据：Mica `NowPlayingLyricsExpanded.kt`、`LyricsOwnedPositionMotion.kt`、真实 `ExpandedLyricsPanel` 回归及 Android12 真机证据；172项场景索引见 `SCENARIO_LEDGER.csv`。
> 本文先定义“用户看见什么、操作后应发生什么”，而非现有 `pin` / spring / callback 的实现方式。
> **在下方“待定决策”被确认前，禁止将提案称作已批准架构或开始覆盖原 B3 的生产实现。**

## 0. 范围及非目标

重写范围：**展开歌词页（ExpandedLyricsPanel）的滚动决策、间奏结构变化协调、布局几何过渡和位置动画生命周期**。覆盖竖屏/横屏/不同主题中复用该组件的行为，以及动态歌词的视觉呈现。

必须保留而不重写的已有领域能力：
- LRC/ELRC/TTML/内嵌歌词的解析、候选优先级和歌词文档语义；歌词来源不是位置动画层的权威。
- 逐字高亮、翻译/双语、罗马音、文本配色、按压反馈、原有淡入淡出等独立视觉能力。
- 点击某句请求播放 Seek、可调当前行锚点、字号/行距设置、无歌词占位、页面进入退出。
- 列表虚拟化与真实触摸操作；继续使用真实布局测量而非按固定行高推导每行视觉位置。

不扩大到通知栏歌词、桌面歌词、SMB或音频播放引擎；它们提供歌词/播放时间输入，不被重写。

## 1. 三层契约

### Behavior Contract —— 外部可观察，不因重写改变

**B-01 当前句跟随**：处于“自动跟随”模式时，播放时间使当前行变化，当前行向用户设置的锚点平滑移动，非当前行按已有层级显示；没有从顶部/底部错误飞入。

**B-02 间奏进入**：满足既有时间轴语义时出现三点间奏。间奏**插入本身**对“间奏后首行”不得带来额外可见位置跳跃（与自然自动跟随位移分账；既有设备门槛 <8设备像素）。间奏前歌词正常让位，三点可淡入。

**B-03 间奏持续**：间奏是时间轴中的“可呈现条目”，**不是锁定所有后续歌词的状态**。下方歌词在不发生用户或正常跟随动作时稳定；任何真实滚动都必须对整列列表生效。用户上滑、下滑和甩动时，同一列表中可见的前后歌词应该服从相同的实际列表位移，不得上下撕裂。

**B-04 间奏退出**：三点淡出并移除，下一句恢复正常的自动跟随；若用户正在手动拖动，当前手势必须保持权威。不能留下额外 ghost item、过期 pin 或旧行反向下落。

**B-05 暂停与恢复**：暂停音乐只冻结播放时间推进，不禁用歌词列表手动滚动，也不能冻结正在消费的用户手势；恢复播放按明确的“手动浏览恢复策略”（待决策 D1）转回跟随。

**B-06 手势**：手指拖动、fling、反向拖动、手势取消应有连贯列表运动。按压/点击一行请求 Seek，不应让已取消的手势被当作点击，也不应把旧动画留下。

**B-07 Seek 与切歌**：任意时间、间奏中、滚动中、回收中、动画中均可 Seek；最终位置只对应最后一次有效命令。不同歌曲/歌词文档间不保留上一首的坐标、动画、时间轴或隐形条目。

**B-08 布局变动**：字体、翻译、字号、行距、锚点、viewport、旋转/分屏等重排后，按真实尺寸重新确定目标；不复用过期像素坐标。视觉与点击命中区域尽可能一致，不发生长期视觉/布局脱节。

**B-09 动画开关/性能**：关闭动效、低帧率、掉帧、页面遮挡、后台恢复等情况，最终位置仍正确；动画是可中断的呈现过程，不是业务事实和播放时间权威。

**B-10 安全与资源**：只读用户歌曲；view geometry、任务、快照、缓存有界，长期滚动几千行不能按全部历史访问行累计永久状态；页面关闭后不再执行旧动画 side effect。

### Architecture Contract —— 变更须有明确决定

**A-01 单一物理滚动权威**：最终列表滚动位置由一个 Scroll Coordinator 经由真实 `LazyListState` 处理；动画层不得暗中发起第二组同源滚动指令。

**A-02 动画不夺走滚动权威**：所需过渡只允许基于当前版本的真实 item 测量建立**暂态、可中断的结构性位置残差**。不能为实现“插入瞬间下方不跳”而对整段间奏维持固定绝对 Y。

**A-03 位置身份与版本**：每个动画事务带 `song/lyrics revision + viewport/layout revision + seek generation + interlude identity`。版本变化使旧事务失效；取消不能让旧回调在新状态重新写入坐标。

**A-04 可解释位移**：`最终视觉 Y = 当前布局测得的 Y + 合法且有界的过渡残差 + 独立视觉特效偏移`。任何残差必须有明确的源、开始/结束及取消条件；用户手势的真实滚动绝不可被用于保留旧绝对坐标的残差抵消。

**A-05 幂等提交**：同一布局插入/移除只结算一次，即使 `onPlaced` 和 `snapshotFlow` 同帧/多次触发也不得重放补偿。不同来源的滚动实际消费值分别标记，但只有一个地方决定最终请求。

**A-06 有界快照与回收**：仅保存本次布局事务相关的少量已测量可见 key；事务成功、取消、离开可视区、切歌和关闭页面时释放。不得持续缓存整首歌所有曾出现过的完整歌词文本 key。

## 2. 两条彼此独立的状态轴（防止“间奏=锁定”）

### 轴 S：用户/播放滚动控制权

| 状态 | 谁可请求真实滚动 | 转移触发 | 可观察行为 |
|---|---|---|---|
| `FOLLOWING` 自动跟随 | 自动跟随协调器（仅最新时间轴） | 页面创建、主动返回当前行、手动浏览策略到期 | 切句时向设置的当前行锚点跟随 |
| `BROWSING_DRAG` 手动拖动 | 用户手势是最高优先级 | 用户按下并超过拖动阈值 | 所有可见行跟手；暂停/间奏也一致 |
| `BROWSING_FLING` 惯性浏览 | 先前用户手势的惯性动量 | 手指松开时的 fling | 惯性停止前不得被过期跟随或 pin 抢走 |
| `BROWSING_HOLD` 浏览保持 | 暂停自动跟随并保持当前真实列表位置 | fling 停止后 | 恢复策略由 D1 决定，不能由间奏是否存在暗中决定 |
| `SEEKING` 明确重定位 | 最新 Seek 或歌曲/文档身份更新 | 点击歌词、进度条提交、切歌 | 先取消旧位置事务，重新测量并定位；完毕由规则回到 FOLLOWING/BROWSING |
| `REFLOW` 视口/字体/锚点重排 | 布局事务（不能抹掉手势 authority） | 配置/几何变化 | 以新 viewport/行高重算目标，不带旧 pin；若正在手势中，手势优先 |

优先级的**行为目标**：安全重置（换歌/lyrics更新/显式Seek） > 正在发生的用户手势与fling > 有效重排 > 合法的当前行自动跟随 > 纯视觉动画。具体 Seek 是否应中断当前手势的手感由 D2 确认。

### 轴 I：与滚动模式正交的间奏阶段

| 阶段 | 条件 | 允许补偿行为 | 禁止行为 |
|---|---|---|---|
| `NONE` | 没有间奏条目 | 无 | 继续持有旧间奏快照 |
| `ENTERING` | 时间轴决定新增间奏且布局尚未稳定 | 捕获下一行有版本的前/后测量，**一次性**保持插入视觉连续性 | 固定高度盲目 scroll；无限期 pin |
| `PRESENT` | 三点已进入稳定布局 | 普通列表滚动/自动跟随按轴S规则；三点自己的点动效 | 以 ENTERING 快照覆盖用户当前滚动 |
| `EXITING` | 三点移除/淡出，回到普通行结构 | 受控退场与一次性布局结算 | ghost 元素锁住后续歌词或遗留过期动画 |

关键：任何组合 `S × I` 都应有明确行为，例如 `BROWSING_DRAG × PRESENT`、`BROWSING_FLING × ENTERING`，不是“先判断 interlude 存在就固定所有后续行”。

## 3. 必须逐个验证的事件矩阵（行为优先，不写实现补丁）

| 事件 | FOLLOWING + NONE | FOLLOWING + ENTERING/PRESENT | BROWSING_DRAG/FLING + PRESENT | SEEKING/REFLOW + 任意 |
|---|---|---|---|---|
| 新歌词行成为当前 | 自动平滑跟随 | 只走一条合法的跟随链 | 不抢用户手势，恢复后重新收敛 | 旧动画失效，当前版本重测量 |
| 间奏进入 | 进入 ENTERING，插入后首行视觉连续 | 禁止重复结算 | 所有歌词随用户实际滚动；插入本身只做一次补偿 | 丢弃旧 receipt，按新身份计算 |
| 间奏退出 | 淡出并恢复普通布局 | EXITING 一次性移除 | 手势不中断，不能拉回旧 Y | 不复活前一轮间奏 |
| 用户上/下滑 | 立刻移交给拖动 | 立刻移交；不留下锁定 | 手势 + 惯性都是权威 | 明确操作先后及取消规则 |
| 反向 Seek | 撤销旧自动动画，重定位 | 释放本次间奏快照 | 显式 seek 优先，撤销拖动动画残留 | 最新命令胜出 |
| 字号/翻译/锚点/尺寸变化 | 新布局重新跟随 | 不使用旧 viewport receipt | 保持手势滚动连续 | transaction 按新版本结算 |

## 4. 生命周期与动画交接的可验证规则

1. 页面首次显示：未测量前不得显示“从列表顶部飞到当前行”；首次目标直接 snap 到合法锚点，然后才开放常规动画。
2. 行身份：当前行、前后行、同文本重复行各有唯一身份；不把 LazyList 索引当作长期身份，插入间奏时索引会变化。
3. 视觉过渡只能消费**已实际测量的**有效结构性变化；下一个 key 尚未测量时，安全等待下一帧，绝不能用固定行高推断并长期钉住该行。
4. 间奏进入事务在第一份有效布局完成后即开始关闭；剩余淡入动画不延长事务的可写权限。
5. 拖动/Seek/viewport 修改必须在可观察的切换边界取消或重新基准化旧过渡；旧 coroutine / callback 不允许继续写新版本状态。
6. 如果文本扩展/缩小、双语显示、逐字高亮导致重新测量，在 FOLLOWING 状态允许合理的视觉连续过渡，在 BROWSING 状态不得逆向抵消手势。
7. 后台/熄屏/低帧率只影响视觉帧采样，不影响最终位置。恢复时以最新播放状态与真实 viewport 为准。
8. 每首长歌的临时几何容量应该是 O(可见行数 + 本次受控过渡涉及的常数行数)，不是 O(歌词总行数/历史访问次数)。

## 5. 测试门禁（先有可失败的合同，再写替代实现）

**T0 / RED**：保留现有 `ExpandedLyricsStage1GestureTest` 与 XML，已确实在原B3复现同一手势：上方 -625.7565px，下方 0px。新架构通过时同场景应 GREEN；不准删除/降低断言来求绿色。

**T1 / Behavior**：间奏17s/55s插入额外漂移 <8设备像素；暂停上滑/下滑、播放中上滑/下滑，手势后上下行同向且位移差按显示/行高变化进行合理归一化；松手惯性与恢复时不得被旧pin拉回；29s/68s自然退出正常。

**T2 / Architecture**：scroll、layout、position residual 每种来源有唯一权威；每次补偿一次消费，超期事务不得在 Seek 或重建后提交；key 与 geometry 缓存数量有硬上界并在退出后释放。

**T3 / Implementation**：现有45/45 B3定向回归先整体保留；进一步补真实 ExpandedLyricsPanel 的手势与插入同帧、拖动跨间奏、返回当前行、低帧率、屏幕尺寸/行高变化。纯逻辑/假 LazyList 测试不代替真机。

**T4 / Device**：Android12 同一测试机（独立包）对照现有 17/55s 录屏与手势录屏；至少25%/60%锚点、正常播放/暂停、字体换行、快速Seek。其他主题、比例、真实音频属于后续发布级 E2E，不能称已覆盖。

## 6. 待产品决定的行为（未确认不得自行假定）

| Decision | 具体冲突 | 建议默认 / 等待确认 |
|---|---|---|
| **D1 手动浏览后何时重新自动跟随** | 播放继续切句时是否马上强制滚回，或保留用户浏览位置？ | 建议拖动/甩动期间绝不抢控；结束后进入 BROWSING_HOLD，**约3–5秒无操作后自动平滑回当前行**。这可能与现有“下一次切句立即跟随”不同，必须由用户确认。 |
| **D2 显式 Seek 在拖动期间触发** | Seek 是否立即取消手势和fling，或延迟交接？ | 建议显式 Seek 是新的最高播放定位意图，可立即取消旧浏览过渡并定位新目标；同一手势不会额外触发点击。 |
| **D3 间奏暂停期间** | 点动效与音乐时间联动吗？ | 建议三点保持静态；视觉位置仍允许手动浏览；恢复播放才继续点动效。 |
| **D4 页面配置改变时的浏览状态** | 修改锚点/字体/旋转后继续浏览，还是跳到当前行？ | 建议若此前在 FOLLOWING，则跟随新锚点；若此前在 BROWSING，则保持当前浏览内容的可见连续性，待 D1 恢复策略触发。 |
| **D5 当前运动风格** | 沿用目前分行滞后和弹簧参数，还是把重写当作风格重新设计？ | 建议 **沿用现有视觉风格与动画时间**，先重写 position authority，避免重构与视觉改版同时发生。 |
| **D6 时间轴极端输入** | 重叠时间戳、重叠/过短间奏、无歌词/歌词更新 | 建议保留现有解析器与间奏判定（当前阈值7s），但位置层必须可确定性降级、不崩溃；若要改变阈值另开行为决策。 |
